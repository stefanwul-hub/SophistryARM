# CP-019 — installation de l’éditeur et accès sans sa fenêtre

Le rapport CP-018 reçu confirme compilation/signature ARM64, auval réussi, éditeur Cocoa local, imports FXP/AUpreset, 522 paramètres et commandes testées. Les **sept WAV** ont été revérifiés : référence originale, prévalidation et composant enregistré sont identiques en 2/6 canaux ; le WAV du nouvel éditeur, après restauration avant l’initialisation, est identique à la référence stéréo. Voir [la preuve anonymisée](../evidence/mac-cp018-editor-rollback.json).

L’installation n’a cependant **pas été confirmée** : le dernier probe d’éditeur distant a échoué (`Cocoa factory did not return unique controllable views`) puis le script a restauré le composant précédent. L’utilisateur retrouve donc CP-016 et ses commandes génériques dans Logic et Live. Ce rapport ne permet pas de conclure que les hôtes ont refusé l’éditeur CP-018 : il avait été retiré avant ces essais. Le haut de la fenêtre générique Logic est aussi hors écran. Les projets Logic restent silencieux.

## Correctif du test et résultats de l’installation

Le probe CP-018 appliquait à la vue annoncée pour un AU distant deux exigences internes : deux vues distinctes et nos sélecteurs de test Objective-C. macOS peut annoncer une factory de relais dont le cycle de vie et les méthodes diffèrent de notre NSView. Le rapport ne consignait pas la classe annoncée, donc ne permet pas d’identifier précisément laquelle avait été utilisée.

CP-019 garde le test de la factory Cocoa **publiée en processus local**. Pour un moteur réellement instancié avec `LoadOutOfProcess`, il crée notre propre éditeur depuis le bundle et lui fait piloter cet AudioUnit distant : état JSON par octets, import AU/FXP, valeurs des paramètres, commandes et rendu. Il consigne séparément le nom de la factory annoncée par macOS. Ce test **ne certifie pas la fenêtre relayée par l’hôte** ; son affichage dans Logic et Live reste à vérifier. Aucun succès de fenêtre distante n’est inventé pour permettre l’installation.

Les tests de rendu et les comparaisons restent obligatoires, ainsi qu’auval, les contrôles de version et la présence de la propriété Cocoa. Une défaillance conserve la restauration automatique. Le résultat JSON distingue désormais réussite d’auval/audio, réussite de chaque test d’éditeur et confirmation de l’installation. CP-018 indiquait à tort `auval_and_registered_audio_passed:false` dès qu’une autre étape empêchait la confirmation finale.

Le probe capture le statut immédiatement après le rendu. Dans CP-018, son statut final était lu après de nouveaux imports qui remettaient les compteurs MIDI/audio à zéro : ces zéros ne prouvaient pas l’absence d’événements pendant le test. L’affichage du nom AU utilise maintenant le champ `name` de l’état hôte lorsque le moteur répond seulement `empty`, sans changer le chunk ni le calcul DSP.

## Utilisation

Télécharger le lanceur CP-019 indiqué dans le README. Pour installer, fermer Logic et Live puis lancer, sans sudo :

```sh
bash "$HOME/Downloads/Demarrer-Sophistry-CP019.command"
```

La licence et la banque valides enregistrées sont réutilisées. Ajouter `--choose-bank` si le sélecteur de banque doit être affiché à nouveau. Le composant cible reste `/Library/Audio/Plug-Ins/Components/Sophistry.component`, identité originale `aumu/Sop3/LinP`, bundle `com.linplug.au.Sophistry`. Les sauvegardes et le retour à l’ancienne version restent automatiques en cas d’échec.

Après succès, ouvrir une **copie** du projet et afficher l’Éditeur. Si le haut de la fenêtre Sophistry est hors écran, laisser l’hôte ouvert et lancer :

```sh
bash "$HOME/Downloads/Demarrer-Sophistry-CP019.command" --recenter-windows
```

Ce mode ne compile ni n’installe l’AU. Il déplace les fenêtres dont le titre contient Sophistry, dans Logic ou Live, sur l’écran principal et tente de limiter leur taille à la zone visible. Il ne modifie pas le projet. macOS peut demander les permissions Automatisation et Accessibilité de Terminal ; l’accès Accessibilité se règle dans **Réglages Système → Confidentialité et sécurité → Accessibilité**. Si aucune fenêtre correspondante n’est ouverte ou si l’accès est refusé, le script signale l’échec. Il ne réinitialise aucune préférence Logic/Live.

Une fois le haut accessible, choisir la vue Éditeur si la vue Commandes est mémorisée. Jouer quelques notes puis **Copier le diagnostic avant de changer le preset ou la banque**.

Pour recueillir un rapport sans accéder à aucune fenêtre du plugin :

```sh
bash "$HOME/Downloads/Demarrer-Sophistry-CP019.command" --diagnose-only
```

Ce mode compile uniquement un petit inspecteur, vérifie la version réellement chargée, la propriété Cocoa, une éventuelle double inscription AU et l’état sûr du moteur, puis produit `Sophistry-inspection-CP019-<date>.zip`. Il ne remplace rien et peut s’exécuter avec Logic/Live ouverts. **Il crée une instance de contrôle indépendante ; il ne lit pas l’état de la piste déjà ouverte**, donc ne remplace pas le diagnostic de l’éditeur pour comprendre un projet silencieux. Aucune clé, préférence brute, bookmark ou donnée de projet n’est exporté.

Transmettre le ZIP d’installation CP-019 ; si les commandes génériques persistent malgré une installation confirmée, joindre aussi le ZIP d’inspection. Il n’est pas nécessaire de transmettre de nouveau la licence ou les presets déjà fournis.

## Vérifications et limites

[Vérifications de développement](../evidence/cp019-development-checks.json) : 30 tests Python réussis, dont le cas précis où le test d’éditeur échoue après un auval/audio réussi ; quatre binaires Mach-O ARM64 compilés et liés strictement, exports AU/Cocoa vérifiés ; syntaxe Bash et JavaScript contrôlée. Les sources du moteur et du lifter restent inchangées depuis CP-018.

CP-019 n’a pas encore été exécuté sur macOS. Les nouveaux tests, l’inspecteur et le recentrage de fenêtre doivent y être vérifiés. L’éditeur reste partiel ; le rappel sonore des anciens projets, la totalité des banques et le fonctionnement en charge réelle ne sont pas validés.
