# CP-009 — émission étendue et construction du synthétiseur

L’Audio Unit installable reste absent. Ce checkpoint étend la traduction à l’ensemble des instructions actuellement reconnues par Ghidra. Il ne prouve pas que toutes les instructions exécutables ont été découvertes ni que le moteur complet fonctionne.

## Résultats vérifiés

- 186001 instructions reconnues, 732177 opérations p-code, C++ fixe réparti en 364 unités plus le dispatch. Aucun décodeur x86 au runtime.
- Les 366 objets (runtime inclus) compilent sous Linux x86_64, ARM64/Linux et Mach-O ARM64. Les objets Mach-O totalisent 28046640 octets. Cette version n’a pas été exécutée sous macOS.
- Avec la bibliothèque complète, les 704 références DSP / 5420672 octets passent sous Linux natif et ARM64/Linux/QEMU, sans différence avec les réponses mathématiques enregistrées.
- 11631 cas différentiels de primitives : SAR immédiat/CL et flags définis, DIV/IDIV et exceptions, SQRTSS avec conservation des voies hautes, FLDZ/FLD1 et pile logique. Quatre gardes explicites s’ajoutent aux fixtures, soit 11635 replays. Zéro différence, y compris sous ARM64/Linux/QEMU.
- Les divisions sont contrôlées aussi avec de vraies instructions x86 à opérandes 32 bits. Unicorn 2.1.4 provoque un SIGFPE de son propre processus pour INT64_MIN / -1 ; ce cas est vérifié par l’oracle matériel, sans être supprimé.
- Les 121 initialisateurs et le constructeur Kaja retournent dans le même hôte de test, en i386/Unicorn et en C++ traduit. Les empreintes des zones globales, objet et tas (4400240 octets au total), ainsi que les appels hôtes, correspondent. L’objet expose 128 programmes, 602 paramètres VST et l’identifiant Sop3.

Le chargeur `scripts/legacy_image.py` place les vrais segments Mach-O à leurs adresses, remplit bss/common de zéros et décrit 404 imports de fonctions, 12 pointeurs importés et 254 relocations externes. Copier tout le fichier brut à l’adresse zéro ne reproduit pas ce chargement : les offsets de __IMPORT/__LINKEDIT diffèrent de leurs adresses virtuelles. Les anciennes fixtures de routines isolées restent des tests à entrées contrôlées, sans initialisation du synthétiseur.

## Limites de l’hôte d’initialisation

`tests/probe_engine_initialization.py` est un prototype Python de services hôtes, pas l’hôte C++ de production. Son allocateur borné suit les libérations sans réutiliser les blocs. Les mutex sont modélisés pour un seul CPU ; les opérations qui bloqueraient arrêtent le test. L’horloge est figée à la date de la tâche, les flux aléatoires sont déterministes et les maths viennent de Linux. Le scénario rend le profil ColorSync, le bundle CoreGraphics et l’ancien libSystem indisponibles : le code original suit ses branches d’erreur. L’enregistrement complet des destructeurs n’est donc pas validé. Aucun changement de code original n’est appliqué à ces branches.

Les services flottants/rand de cet hôte ne constituent pas une exécution des bibliothèques Apple i386. La provenance du rand Darwin consulté est conservée avec son copyright et sa licence sous `reference/host-support/`.

## Point d’arrêt du moteur

La tentative d’ouverture VST (`effOpen`) révèle une adresse valide absente de l’export Ghidra initial : `0x94e41`. Le C++ s’y arrête explicitement. L’original poursuit jusqu’à `_GetMainEventLoop`, un service Carbon absent du prototype.

Il faut récupérer ces blocs de dispatch, puis terminer les services hôtes et le chargement sémantique du preset. Émettre tout le listing Ghidra n’équivaut donc pas à récupérer tout le code atteignable. Les quatre instructions gardées (INT3, LOCK, deux OUT) apparaissent dans des tables de sauts inline interprétées comme du code par Ghidra ; leurs octets de données sont conservés et elles ne sont pas transformées en no-op.

## Reproduction

Le C++ généré est déjà sauvegardé sous `src/lifter/whole/`. Avec Xcode sur Mac ou un compilateur C++ sous Linux :

```sh
bash scripts/build-lifter-chunks.sh
work/lifter-whole/LiftedProbe reference/Sophistry.i386 evidence/static-lift-comparison.fixtures
work/lifter-whole/InstructionProbe reference/Sophistry.i386 evidence/primitive-instructions.fixtures
```

Le build Mac impose ARM64 et macOS 11 minimum. Le script Verifier-Mac.command et le lanceur CP-008 restent les vérificateurs du jeu sélectionné précédent. Aucun de ces scripts n’installe un composant.

Pour régénérer vers un dossier vide, avec Python standard :

```sh
python3 scripts/lift_pcode_chunks.py analysis/lifter-full/instructions.jsonl.gz work/regenerated-whole
```

Les comparaisons i386 utilisent les dépendances de requirements-analysis.txt. Le projet Ghidra est sauvegardé pour récupérer les blocs manquants.
