Écart confirmé, laissé intact pour le retour strict : `configuration()` active `deterministicTestHost=true`, `_mach_absolute_time` avance de 1000 ticks par requête, `_mach_timebase_info` renvoie 1/1. L’original utilise sa fonction de temps `0x2e1c0` notamment pour le contrôle/MIDI. Les timestamps AU natifs transitent aussi dans cette adaptation : leur unité doit être réexaminée. Aucun lien causal avec le surcoût CPU n’a été démontré. Le mode SSE3 original est bien sélectionné ; aucune arithmétique x87 étendue n’a été détectée dans l’inventaire. Le `dlopen` libSystem absent concerne ici l’enregistrement de destruction globale, pas une preuve de voie DSP rapide manquante.

Ne pas annoncer une équivalence exhaustive ni une parité CPU CronoX. Le C++ statique conserve état de registres virtuels, contrôles mémoire et suivi par instruction ; ce coût existe, sans explication quantitative établie de l’écart CP032/CronoX. Aucune nouvelle optimisation ni correction sémantique du moteur n’est appliquée dans CP034.
